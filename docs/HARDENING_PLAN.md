# Claude: Hardening & Reliability Plan

This document outlines the architectural and quantitative requirements for transitioning the `moomoo-trader` system from a "Functional Research" state to a "Production-Grade" state.

---

## 1. Risk Normalization (ATR-Based Sizing)
**Reasoning:** The current system uses "Blind Sizing" (fixed dollar cap). If volatility is high, the stop is wide, and we risk a large portion of our equity. If volatility is low, we risk very little. This leads to an erratic equity curve where one high-volatility loss wipes out multiple low-volatility wins.

### Task: Implement "Dollar-at-Risk" Model
- **Refactor `mm/risk.py`:** Create a new function `calc_atr_qty(price, stop_dist, risk_dollars)`.
- **Logic:** `qty = risk_dollars / stop_dist`.
- **Config:** Add `RISK_DOLLARS_PER_TRADE` to `.env` and `mm/config.py`.
- **Integration:** Update the `_eval_*` functions in `mm/paper.py` to use this new sizing logic.
- **Rule:** If `FRACTIONAL_SHARES=true`, return the float. If `false`, return `math.floor()`.

---

## 2. Real Telemetry (Slippage Truth)
**Reasoning:** Currently, `slippage_bps` in the logs is hardcoded to `0.0` because the runner uses the same `close` price for the signal, the order placement, and the log entry. We are blind to the "Lag Tax" of 60s polling.

### Task: Correct intended_price capture
- **In `mm/paper.py`:** Capture `intended_price = close` at the exact moment the signal evaluates to `True`.
- **The Gap:** Pass this `intended_price` through to the `order_attempt` and then to the `position_open` event.
- **The Result:** The dashboard's "Slip" column will now show real values (e.g., 2.5 bps) instead of 0.0.

---

## 3. "Self-Healing" Broker Reconciliation
**Reasoning:** The bot currently only checks its memory (local JSON) against the broker reality (OpenD) at **startup**. If the API rejects an order or a trade is closed manually during the day, the bot will "hallucinate" a position that doesn't exist.

### Task: Implement Periodic Soft Reconciliation
- **In `mm/paper.py`:** Move the `_reconcile_positions` logic into the main loop.
- **Frequency:** Run it every 10–15 poll cycles (10-15 minutes).
- **Action:** If the broker has no position but a local state file exists: **Delete the local file and send a CRITICAL alert to Discord.** This makes the bot self-healing.

---

## 4. Strategy "Fairness" Guards
**Reasoning:** `MAX_TRADES_PER_DAY` is currently a global cap. A fast-moving strategy like ORB can consume all 3 slots by 9:40 AM, starving the "Sniper" strategies (BB+KDJ) for the rest of the day.

### Task: Implement MAX_TRADES_PER_STRATEGY
- **Config:** Add `MAX_TRADES_PER_STRATEGY` to `mm/config.py`.
- **Logic:** Update `DailyTracker` in `mm/risk.py` to track counts per strategy tag.
- **Goal:** Ensure every strategy gets a chance to trade regardless of which one fires first.

---

## 5. Documentation Consolidation
**Reasoning:** The project has multiple source-of-truth files (`CLAUDE.md`, `PROJECT_MAP.md`, `README.md`) which are starting to contradict each other.

### Task: Housekeeping
- **Prune `CLAUDE.md`:** Remove historical research findings. Keep it strictly for current session instructions and the "Immediate Backlog."
- **Update `PROJECT_MAP.md`:** This is now the "Master Fact Sheet." Move the "Strategy Findings" table from `CLAUDE.md` into this file.
- **Delete redundant files:** Once this plan is executed, any transitionary notes should be consolidated or removed.
